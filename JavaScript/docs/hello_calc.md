## 実務での型（よく使うパターン）
学習の次の段階として、読みやすさ・事故りにくさを上げる改善。

### 1) `const` を基本にする
`a` と `b` を変えないなら `let` ではなく `const` を使う。

- 変える予定があるときだけ `let`

### 2) 何の計算結果か分かるように表示する
数字だけ出すと、あとで見返したときに意味が分からなくなりがち。

- 例: `console.log(`${a} + ${b} = ${a + b}`)`

### 3) 入力が文字列のときは数値に変換する
コマンド引数や入力欄から来た値は **文字列** のことが多い。

- `Number(value)` で数値化
- `Number.isNaN(...)` でチェック

---

## 落とし穴（よくあるエラーと回避策）
- **`+` は文字列連結にもなる**
  - `"1" + "2"` は `"12"`（足し算ではなく結合）
  - 入力が文字列の可能性があるなら `Number(...)` を使う
  - 詳細：JavaScript の `+` は **どちらか一方でも文字列が混ざると**、数値の足し算ではなく **文字列として連結**しようとします。
    - `1 + 2` → `3`（数値）
    - `'1' + 2` → `'12'`（文字列。2 が文字列に変換されて連結）
    - `1 + '2'` → `'12'`
    - `'1' + '2'` → `'12'`
  - つまづき例：入力はほぼ文字列
    - ブラウザの `prompt()` は文字列を返す
    - Node.js の `process.argv` も文字列
  - 対策：計算する前に数値へ変換する
    - `Number('10')` → `10`
    - `Number('')` → `0`（空文字は 0 になるので注意）
    - `Number('abc')` → `NaN`（`Number.isNaN(...)` でチェック）
    - 小数も扱うなら `Number` or `parseFloat`、整数だけなら `parseInt(value, 10)`
  - 参考：`- * /` は文字列が混ざると数値変換が起きやすい（例：`'10' - 1` → `9`）ので、`+` だけ挙動が違って見えて混乱しやすい
- **割り算は小数になる**
  - 必要なら丸める（`Math.round` など）
- **`let` と `const` の使い分け**
  - 変えない値に `let` を使うと、後で意図せず書き換えてバグになりやすい

## 補足：`${a}` の記法（テンプレートリテラル）
`${a}` は **テンプレートリテラル**（バッククォート `` `...` ``）の中で、変数や式を文字列に埋め込む記法です。

- `${a}`：変数 `a` の値を埋め込む
- `${a + b}`：式の計算結果を埋め込む

例（`hello_calc.js` の出力を分かりやすくする）：

```js
const a = 25;
const b = 10;

console.log(`${a} + ${b} = ${a + b}`);
```

よくある間違い：

```js
console.log('${a}'); // これは展開されず、そのまま "${a}" と表示される
console.log(`${a}`); // これが展開される
```

## `hello_calc.js` レビュー（改善ポイント）
現状のコードは「Hello を出す」「四則演算して表示する」を満たしていて、Week1 の最小実装としてOKです。

改善すると学びが増えるポイントは次の通りです。

1) `let` → `const`（再代入しないため）
- `a` と `b` を固定値で使うだけなら `const` が適切です。

2) 演算子の前後にスペース（読みやすさ）
- `a+b` より `a + b` の方が読みやすいです。

3) 出力にラベルを付ける（何の結果か分かるように）
- 数字だけだと、後で見返したときに「どれが足し算？」となりやすいです。

例：

```js
console.log(`${a} + ${b} = ${a + b}`);
console.log(`${a} - ${b} = ${a - b}`);
console.log(`${a} * ${b} = ${a * b}`);
console.log(`${a} / ${b} = ${a / b}`);
```

4) （次の段階）入力が文字列のときは `Number(...)` で数値化
- CLI引数やユーザー入力は文字列になりがちなので、数値に変換してから計算すると事故が減ります。

## 補足：JavaScript のデータ型と変数宣言

### データ型（ざっくり分類）
JavaScript の値は大きく **プリミティブ型** と **オブジェクト型** に分かれます。

- プリミティブ型（基本の値）
  - `number`：数（整数も小数も同じ。例：`10`, `2.5`）
  - `string`：文字列（例：`"hello"`, `'hello'`, `` `hello` ``）
  - `boolean`：真偽値（`true` / `false`）
  - `null`：明示的に「空」を表す
  - `undefined`：未定義（値が入っていない）
  - `bigint`：とても大きい整数（例：`123n`）
  - `symbol`：一意な識別子（入門では後回しでOK）
- オブジェクト型
  - `object`：オブジェクト、配列、関数、Date など

型の確認（よく使う）

```js
const a = 25;
console.log(typeof a); // "number"
```

注意：`typeof null` は歴史的な理由で `"object"` になります（よくある例外）。

### 変数宣言：`var` / `let` / `const`
結論として、基本は **`const` を使い、必要なときだけ `let`** を使います。

- `const`：再代入できない（安全）
- `let`：再代入できる（必要なときだけ）
- `var`：古い書き方。スコープが分かりにくくなりやすいので基本使わない

例：この課題の `a` と `b` は変えないなら `const` が自然です。

```js
const a = 25;
const b = 10;
// a = 30; // これはエラー（再代入）
```

スコープ（有効範囲）の違い（重要）
- `let` / `const`：ブロックスコープ（`{ ... }` の中で有効）
- `var`：関数スコープ（ブロックをまたいで見えてしまい混乱しやすい）

# 数当てゲーム（prompt版）メモ

このドキュメントは、Week1 のお題「数当てゲーム（コンソール版）」を **ブラウザの `prompt()`** を使って実装する学習ログです。

- 対象コード: `JavaScript/src/number_guess.js`
- 実行用HTML: `JavaScript/src/number_guess.html`
- 目的: 乱数 / `if` / `for` / 型変換 / 入力と出力の流れに慣れる

---

## 概念（何を解決するか）
「ランダムに決まった答え」をユーザーが推測し、ヒント（大きい/小さい）を出しながら当ててもらうゲーム。

この課題でできるようになること
- 乱数で答えを作る
- 入力（`prompt`）を受け取る
- 比較して条件分岐する
- 回数制限のあるループを書く

---

## 最小実装（Hello World レベルで動かす）
要件を満たす最小は次。

1. 1〜10 の整数 `answer` を1つ生成する
2. `prompt()` で推測を受け取る
3. `if` で比較して「大きすぎ / 小さすぎ / 正解！」を出す
4. `for` で最大3回まで繰り返す（正解したら `break`）

---

## 実務での型（よく使うパターン）
最小実装から一段だけ安全にするための「型」です（実務っぽい考え方）。

### 1) 入力は必ず数値へ変換してから使う
`prompt()` の返り値は文字列なので、比較や計算の前に数値へ変換する。

- `const guess = Number(input)`
- 変換できない場合は `NaN` になるのでチェックする（後述）

### 2) 変数は「再宣言」ではなく「更新」する
同じ名前で `let` を内側に書くと、外側の変数を更新できずにバグになりやすい。

- OK: `userNum = prompt(...)`（更新）
- NG: `let userNum = prompt(...)`（別変数を作りやすい）

### 3) ループ回数は仕様から逆算する
- 最大3回 → `for (...; ... < 3; ...)`

---

## 落とし穴（よくあるエラーと回避策）
コードレビューでよく指摘される「技術知識ポイント」をまとめます。

### 1) 乱数が小数のまま
- `Math.random() * 10` は 0〜10未満の小数。
- 1〜10の整数にするには次の形を使う：
  - `Math.floor(Math.random() * 10) + 1`

### 2) `prompt()` は文字列を返す
- 例: `prompt()` の結果は `'5'` のような文字列。
- そのまま比較すると挙動が分かりづらくなるので、`Number(...)` に通す。

### 3) `NaN`（数値に変換できない入力）
- `Number('abc')` は `NaN`。
- `NaN` は比較すると全部 `false` になりやすく、意図しない `else` に落ちる原因になる。
- 対策: `Number.isNaN(guess)` を使って弾く。

### 4) キャンセル（`null`）
- `prompt()` でキャンセルすると `null` が返る。
- `Number(null)` は `0` になるので、キャンセルを 0 として扱ってしまう事故が起こる。
- 対策: `if (input === null) { ... }` で分岐する。

### 5) `for` の回数がズレる
- `i < 2` だと 2回。
- 仕様が「最大3回」なら `i < 3`。

### 6) ブラウザと Node.js の違い
- `prompt()` は **ブラウザ専用**。
- Node.js で `node number_guess.js` をすると `prompt is not defined` になる。

### 7) 正解をログに出してしまう
- `console.log(answer)` を常に出すとゲームにならない。
- デバッグ目的なら一時的に出して、動いたら消す。

## 説明できる状態（チェックリスト）
次を口頭で説明できればOK。

- 1〜10 の整数乱数を作る式が言える
- `prompt()` が文字列を返すので `Number(...)` する理由が言える
- `NaN` と `null` の違いと、両方の対策が言える
- `for` で最大3回をどう書くか説明できる
- `break` が何をするか説明できる
